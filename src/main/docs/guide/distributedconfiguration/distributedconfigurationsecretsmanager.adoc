To use https://aws.amazon.com/secrets-manager/[AWS Secrets Manager] as distributed configuration include the following dependency:

dependency:io.micronaut.aws:micronaut-aws-secretsmanager[]

The recommended way to load Secrets Manager configuration is with `micronaut.config.import`.

.application.yml
[source,yaml]
----
micronaut:
  application:
    name: myapp
  config:
    import:
      - secretsmanager:/config/application
      - optional:secretsmanager:/config/myapp
----

You can also use the structured form:

.application.yml
[source,yaml]
----
micronaut:
  application:
    name: myapp
  config:
    import:
      - provider: secretsmanager
        path: /config/application
      - provider: secretsmanager
        path: /config/myapp
        optional: true
----

If you add `micronaut.application.name: myapp` and start your app in the `dev` https://docs.micronaut.io/latest/guide/index.html#environments[Micronaut environment], a secret such as `/config/myapp_dev/oauthcompanyauthserver` can contribute properties like `micronaut.security.oauth2.clients.companyauthserver.client-id` and `micronaut.security.oauth2.clients.companyauthserver.client-secret` to your application.

To avoid secret key naming collisions in the Micronaut application context, configure grouped prefixes. For example, if you would like to use multiple RDS instances, configure it as follows:

.application.yml
[source,yaml]
----
aws:
  secretsmanager:
    secrets:
      - secret-name: rds
        prefix: datasources.default
      - secret-name: rds_backup
        prefix: datasources.backup
----

Note that `secret-name` is a name suffix of the secret configured in AWS Secrets Manager. For example, to add `rds_backup` configuration for a `production` environment, create a secret named `/config/application_prod/rds_backup` or `/config/[APPLICATION_NAME]_prod/rds_backup`. The `prefix` value is prepended to all keys that belong to the matching secret.

Authentication and AWS client configuration options can also be supplied directly on the import declaration.

For connection-string declarations, use the user-info portion for credentials and query parameters for supported options:

.application.yml
[source,yaml]
----
micronaut:
  config:
    import:
      - "secretsmanager://ACCESS_KEY_ID:SECRET_ACCESS_KEY@/config/myapp?aws.region=eu-west-1"
----

For structured declarations, use the same documented Micronaut AWS credential keys (`aws.access-key-id`, `aws.secret-access-key`, `aws.secret-key`, `aws.session-token`, `aws.region`). Use the `secrets` list in the structured form when you need `secret-name` / `prefix` mappings.

Secrets Manager imports also support Micronaut's standard retry declaration options. You can set them either as query parameters on the connection string or as keys in the structured map declaration.

.Supported Secrets Manager import options
[cols="1,2,2"]
|===
| Query parameter / map key | Description | Example

| `aws.access-key-id`
| AWS access key ID. In connection strings, this is normally supplied as the username portion of `ACCESS_KEY_ID:SECRET_ACCESS_KEY@...`.
| `secretsmanager://ACCESS_KEY_ID:SECRET_ACCESS_KEY@localhost/config/myapp?aws.region=eu-west-1`

| `aws.secret-access-key`
| AWS secret access key. In connection strings, this is normally supplied as the password portion of `ACCESS_KEY_ID:SECRET_ACCESS_KEY@...`.
| `secretsmanager://ACCESS_KEY_ID:SECRET_ACCESS_KEY@localhost/config/myapp?aws.region=eu-west-1`

| `aws.secret-key`
| Alternate Micronaut AWS secret-key property supported in structured map declarations.
| `aws.secret-key: my-secret-key`

| `aws.session-token`
| Optional AWS session token.
| `secretsmanager:/config/myapp?aws.session-token=token123`

| `aws.region`
| AWS region used by the importer-owned client context.
| `secretsmanager:/config/myapp?aws.region=eu-west-1`

| `secrets`
| Structured-map-only list of secret grouping definitions. Each entry can include `secret-name` and `prefix` to remap keys from a matched secret.
| `secrets: [{ secret-name: oauthcompanyauthserver, prefix: datasources.default }]`

| `retry-attempts`
| Maximum number of import attempts.
| `secretsmanager:/config/myapp?retry-attempts=5`

| `retry-count`
| Alias for `retry-attempts`.
| `retry-count: 5`

| `retry-delay`
| Delay between retry attempts.
| `secretsmanager:/config/myapp?retry-delay=250ms`

| `retry-max-delay`
| Maximum overall retry delay.
| `secretsmanager:/config/myapp?retry-max-delay=5s`

| `retry-multiplier`
| Backoff multiplier applied to each delay.
| `secretsmanager:/config/myapp?retry-multiplier=1.5`

| `retry-jitter`
| Jitter factor between `0.0` and `1.0`.
| `secretsmanager:/config/myapp?retry-jitter=0.2`
|===

IMPORTANT: This change does not add AWS watch/refresh support. Imported Secrets Manager values are resolved at startup only.

[NOTE]
====
The legacy bootstrap/context configuration client path remains available for migration, but it is deprecated. Existing applications using `src/main/resources/bootstrap.yml` with `micronaut.config-client.enabled=true` and `aws.secretsmanager.enabled=true` will continue to work for now.
